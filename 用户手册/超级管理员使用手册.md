## 第一章 概述

### 1.1 超级管理员权限范围

超级管理员（superadmin）是系统的最高权限账号，拥有以下专属能力：

| 模块 | 普通管理员 | 超级管理员 |
|------|-----------|-----------|
| 创建/删除租户 | ❌ | ✅ |
| 跨租户操作 | ❌ | ✅ |
| 全局系统参数 | ❌ | ✅ |
| 数据库迁移 | ❌ | ✅ |
| 备份恢复 | ❌ | ✅ |
| 密钥管理 | ❌ | ✅ |
| 监控告警 | ❌ | ✅ |

> 警告：超级管理员操作影响全局，请谨慎。

### 1.2 多租户架构

系统采用 schema 级多租户隔离：

```
public schema（全局）
├── tenants（租户表）
├── users（含 superadmin 的全局账号）
└── 公共配置

tenant_a schema（租户 A）
├── users（租户 A 的用户）
├── courses（租户 A 的课程）
└── ...

tenant_b schema（租户 B）
└── ...
```

每个租户拥有独立的数据库 schema，数据完全隔离。

### 1.3 登录系统

1. 打开浏览器访问系统地址
2. 输入用户名 `superadmin001`、密码 `bcs19800403`
3. 点击 **登录**

## 第二章 租户管理

### 2.1 租户列表

![租户列表](images/superadmin/sa_01_tenants.png)

**功能描述**：查看和管理所有租户。

**页面说明**：
- 表格字段：租户 ID、名称、schema 名、状态、创建时间、用户数
- 操作：创建、编辑、删除、迁移、切换

**操作步骤**：

#### 创建租户

1. 点击 **创建租户**
2. 填写：
   - 租户名称（如 "北京大学"）
   - schema 标识（自动生成，可手动调整，建议简短英文）
   - 管理员账号、初始密码
   - 管理员邮箱
3. 选择套餐版本：试用版 / 标准版 / 企业版
4. 点击 **保存**
5. 系统自动：
   - 在 PostgreSQL 创建 schema
   - 运行迁移初始化数据库结构
   - 创建租户管理员账号
   - 初始化默认数据

#### 编辑租户

1. 找到目标租户
2. 点击 **编辑**
3. 修改租户信息
4. 保存

#### 切换租户

1. 在租户列表点击 **切换**
2. 系统切换到该租户上下文
3. 左侧导航变为该租户的管理菜单
4. 可执行该租户内的所有管理员操作

#### 删除租户

1. 点击 **删除**
2. 二次确认（需输入租户名称）
3. 系统删除租户及所有关联数据
4. **操作不可恢复**

> 警告：删除租户会删除该租户下所有用户、课程、数据，请提前备份。

#### 导出租户

1. 点击 **导出**
2. 选择导出内容：基础信息 / 全量数据
3. 下载

### 2.2 租户配置

**入口**：租户列表 → 配置

**功能描述**：为每个租户定制化配置。

**操作步骤**：
1. 进入租户配置
2. 修改配置：
   - 功能开关：AI 功能、微专业、考试系统等
   - 容量限制：用户数、课程数、存储空间
   - 域名：自定义访问域名
   - Logo、主题色
3. 保存

## 第四章 数据迁移管理

### 4.1 迁移概览

**功能描述**：查看和管理数据库迁移状态。

**页面说明**：
- 表格字段：租户、迁移版本、状态、时间
- 操作：执行、回滚、生成迁移、导入数据

### 4.2 执行迁移

**操作步骤**：
1. 选择目标租户
2. 查看待执行迁移列表
3. 点击 **执行迁移**
4. 系统按版本顺序执行
5. 显示执行结果

### 4.3 回滚迁移

**操作步骤**：
1. 选择目标租户
2. 选择要回滚的迁移版本
3. 点击 **回滚**
4. 二次确认
5. 系统执行回滚

> 警告：回滚可能导致数据丢失，请提前备份。

### 4.4 生成迁移

**功能描述**：为租户生成新的迁移脚本。

**操作步骤**：
1. 进入迁移生成
2. 选择租户或全局
3. 修改数据库结构
4. 系统生成迁移文件
5. 提交迁移

### 4.5 跨租户数据迁移

**功能描述**：将一个租户的数据迁移到另一个租户。

**操作步骤**：
1. 进入数据迁移
2. 选择源租户、目标租户
3. 选择要迁移的数据类型：用户、课程、知识图谱等
4. 配置映射规则
5. 预览迁移结果
6. 确认执行

### 4.6 迁移幂等性

所有迁移脚本设计为可重复执行（幂等），保证：
- 重复执行不会报错
- 部分失败的迁移可继续
- 支持版本回滚

## 第九章 紧急操作指南

### 9.1 数据库故障

**应急步骤**：
1. 检查数据库连接
2. 启用从库（如有）
3. 查看错误日志
4. 联系 DBA
5. 必要时从备份恢复

### 9.2 服务宕机

**应急步骤**：
1. 检查服务进程
2. 查看日志定位问题
3. 重启服务
4. 如反复失败，使用最近备份恢复
5. 启用灾备节点

### 9.3 数据误删

**应急步骤**：
1. **立即停止写入操作**
2. 评估丢失范围
3. 从最近备份恢复
4. 验证数据完整性
5. 复盘事故原因

### 9.4 安全事件

**应急步骤**：
1. 立即冻结可疑账号
2. 修改超级管理员密码
3. 轮换 API Key
4. 启用 IP 白名单
5. 查看操作审计，定位入侵路径
6. 报告安全团队

### 9.5 紧急联系

| 类别 | 联系方式 |
|------|---------|
| 系统厂商技术支持 | 参见采购合同 |
| 数据库 DBA | 内部运维团队 |
| 云服务商工单 | 阿里云 / 腾讯云控制台 |

## 第二十一章 常见问题

### Q1：超级管理员账号被锁定怎么办？

通过数据库直接解锁或联系数据库管理员重置。

### Q2：迁移执行失败如何处理？

1. 查看失败原因
2. 修复数据问题
3. 重新执行迁移（脚本幂等）
4. 必要时回滚到上一版本

### Q3：如何批量更新所有租户的某个参数？

1. 进入系统配置
2. 修改全局参数
3. 点击 **应用到所有租户**
4. 确认

### Q4：租户数据迁移中途失败？

1. 查看迁移日志
2. 定位失败步骤
3. 修复源数据
4. 重新执行迁移（脚本幂等）

### Q5：如何对租户进行限流？

1. 进入租户配置
2. 设置限流规则：
   - API 调用 QPS
   - 并发用户数
   - 存储空间
3. 启用

### Q6：如何审计超级管理员的操作？

所有超级管理员操作都会记录在：
- 操作审计日志
- 数据库审计表（PostgreSQL audit）
- 系统操作日志

可通过操作审计页面查看。

### Q7：跨租户数据导入的注意事项？

1. 数据格式需一致
2. ID 映射要正确
3. 提前备份目标租户
4. 建议在低峰期执行
5. 执行后验证数据完整性
