## 三、图片命名规范

- 角色前缀：`s_` 学生 / `t_` 教师 / `a_` 管理 / `sa_` 超级管理
- 模块编号：`01` `02` …
- 功能简称：英文/拼音，简短清晰
- 步骤序号（可选）：`_step1` `_step2`

**示例**：
- `s_01_dashboard.png` — 学生端工作台
- `s_05_graph_overview_step1.png` — 学生图谱总览 第1步
- `t_08_exam_create.png` — 教师考试创建
- `a_03_student_list.png` — 管理学生列表

## 四、Markdown 写作规范

### 4.1 章节层级

```
# 手册标题
## 第一章
### 1.1 一级功能
#### 操作步骤
```

### 4.2 功能模块统一模板

每个功能按以下顺序编写：

```markdown
### 1.1 功能名称

**功能描述**：本模块的核心作用（一句话说明）。

**适用场景**：哪些场景会用到该功能。

**入口路径**：登录后 → 顶部导航/侧边栏 → XX 菜单 → XX 页面。

**页面说明**：
- 区域 A：说明
- 区域 B：说明

![功能页面](images/student/s_xx_xxx.png)

#### 操作步骤

1. 第一步：操作描述
2. 第二步：操作描述
   ![子步骤截图](images/student/s_xx_xxx_step2.png)
3. 第三步：操作描述

#### 注意事项

- 关键约束或常见错误

#### 相关功能

- 与本功能相关的其他模块链接
```

### 4.3 图文排版

- 截图前后各留一行空行
- 关键按钮、菜单用 **粗体** 标注
- 路径用 `代码字体`
- 提示用 `> 引用块`

## 九、截图获取流程

### 9.1 工具

推荐使用 Chrome DevTools MCP 工具或 Playwright 自动截图：

```
# Playwright 示例
npx playwright codegen http://localhost:8081
# 登录后进入目标页面，使用浏览器自带截图或 snipping tool
```

### 9.2 截取原则

1. **分辨率**：1440×900 桌面端 / 375×812 移动端
2. **完整页面**：尽量截取完整可见区域
3. **关键操作**：分步骤截图，单独保存子步骤
4. **去除敏感信息**：截图中模糊化姓名、手机号等隐私字段
5. **统一水印**：截图中去除浏览器调试工具栏

### 9.3 提交位置

| 端 | 目录 |
|----|------|
| 学生 | `用户手册/images/student/` |
| 教师 | `用户手册/images/teacher/` |

## 十、格式转换

### 10.1 Markdown → PDF

```bash
# 安装 wkhtmltopdf 或使用 pandoc + LaTeX
pandoc 学生端使用手册.md \
  -o 学生端使用手册.pdf \
  --pdf-engine=xelatex \
  -V mainfont="PingFang SC" \
  -V geometry:margin=2cm \
  --toc --toc-depth=2
```

或使用 weasyprint（中文支持更佳）：

```bash
pandoc 学生端使用手册.md -o student.html \
  --self-contained --metadata title="学生端使用手册"
weasyprint student.html 学生端使用手册.pdf
```

### 10.2 Markdown → DOCX

```bash
pandoc 学生端使用手册.md -o 学生端使用手册.docx \
  --reference-doc=template.docx \
  --toc --toc-depth=2
```

### 10.3 批量转换脚本

见 `用户手册/build.sh`（生成中），可一键构建所有手册的 PDF / DOCX 版本。

## 十一、协作流程

1. **规划阶段**：本文档定义结构与规范
2. **截图阶段**：开发 / 测试同学按章节截取图片，存入对应目录
3. **编写阶段**：按章节模板填写内容，可多人分工
4. **校对阶段**：每个角色找一名真实用户试用并反馈
5. **发布阶段**：生成 PDF / DOCX 分发
