## Context

当前教师端图谱页面 (`src/pages/teacher/graph-*.tsx`) 存在以下问题：

1. **课程选择不统一**：四个图谱页面各自独立管理课程状态，用户切换课程后需要分别选择
2. **命名不清晰**：Tab显示"知识图谱"，未体现知识"关系"的概念
3. **关系过滤功能弱**：当前关系类型选项为静态配置，未基于图谱真实数据，且无点击过滤交互
4. **问题图谱信息不完整**：点击问题节点仅显示基本信息，缺少题目内容和关联知识点
5. **思政图谱功能缺失**：缺少知识点管理模块，关系类型未复用现有类型定义

## Goals / Non-Goals

**Goals:**
- 统一四个图谱的课程选择状态，提升用户体验
- 优化知识关系图谱的关系过滤功能，基于真实数据动态生成
- 完善问题图谱的详情展示功能
- 补充思政图谱的知识点管理功能

**Non-Goals:**
- 不修改图谱的渲染逻辑和算法
- 不新增API接口，复用现有接口
- 不改变现有图谱的数据结构和存储

## Decisions

### D1: 统一课程选择状态管理
**选择**: 使用 React Context 在图谱页面父组件中统一管理课程状态

**理由**: 
- 四个图谱页面是 Tab 切换关系，Context 可以在父组件中共享状态
- 避免 Prop drilling 和状态同步问题
- 与现有项目架构一致 (已使用 @tanstack/react-query)

**备选方案**:
- 使用 URL query 参数 (不选: 需要处理页面刷新状态丢失)
- 使用 localStorage (不选: 多端登录状态不一致)

### D2: 关系过滤数据源
**选择**: 从图谱接口返回的真实关系数据中提取关系类型

**理由**:
- 确保过滤选项与图谱实际数据一致
- 数据驱动，无需额外配置
- 已有 `relationType` 字段在接口返回中

### D3: 问题详情展示方式
**选择**: 使用 Ant Design Drawer 组件展示详情

**理由**:
- 与项目现有 UI 组件库一致
- Drawer 方式不遮挡图谱视图
- 可承载更多详细信息

### D4: 思政图谱关系类型
**选择**: 复用 `knowledge-relation` 页面的 relationType 接口

**理由**:
- 保持关系类型定义的一致性
- 减少重复维护工作
- 与用户需求一致

## Risks / Trade-offs

- [风险] 统一课程状态后，切换课程可能触发多个图谱数据同时加载
  - 缓解: 使用 React Query 的 `keepPreviousData` 和 loading 状态优化

- [风险] 关系类型数据量大时可能影响渲染性能
  - 缓解: 使用 memo 缓存关系类型列表，使用虚拟列表（如需要）

- [风险] 思政图谱新增知识点管理模块需要额外开发时间
  - 缓解: 复用现有知识点组件结构，减少重复开发
