## Context

资源管理页面 (`src/pages/teacher/file.tsx`) 支持批量上传文件到OSS或服务端。当前上传逻辑在用户选择文件后直接开始上传，没有检查是否已存在同名文件。

## Goals / Non-Goals

**Goals:**
- 在文件上传前检测服务器端是否存在同名文件
- 发现重复文件时弹窗提示用户，由用户决定是否跳过或覆盖
- 提供良好的用户体验，不阻断正常上传流程

**Non-Goals:**
- 不修改后端API
- 不实现文件内容级别的去重（仅文件名检测）
- 不处理跨目录的重复检测（当前文件按课程隔离）

## Decisions

### 1. 检测时机：选择文件后、上传前
在用户选择文件后、点击上传按钮时，先查询当前课程下已存在的文件列表，与选中文件的文件名进行比对。

**替代方案A**: 每选择一个文件就立即检测 - 会导致频繁API调用  
**选择方案**:上传 点击按钮后批量检测，性能更好

### 2. 重复处理方式：弹窗确认
检测到重复文件时，弹窗列出所有重复文件名，让用户选择"跳过"或"继续上传"。

**替代方案B**: 直接自动跳过重复文件 - 用户可能不知情  
**替代方案C**: 自动覆盖 - 可能导致数据丢失  
**选择方案**: 弹窗确认最安全，符合用户预期

### 3. 前端实现：不新增Hook/Context
在现有 `file.tsx` 组件内新增状态和方法，不提取独立Hook，保持代码简单。

**替代方案D**: 提取 `useDuplicateCheck` Hook - 过度工程化  
**选择方案**: 组件内实现足够清晰

## Risks / Trade-offs

- [风险] 上传高峰期重复检测API可能有延迟 → 检测在后台进行，不阻塞UI
- [风险] 用户选择大量文件时比对性能 → 仅比对文件名数组，O(n)复杂度可接受
