# OBE导向的高校课程体系设计方案：专业'123'

## 一、培养目标
本专业依据《华盛顿协议》及中国工程教育专业认证标准，构建以学生最终能力达成为核心的OBE（Outcome-Based Education）培养体系。面向软件产业一线程序员岗位需求，培养具备扎实学科基础、突出工程实践能力、健全职业伦理与持续发展素养的高素质应用型人才。

### 毕业要求（12项，对标CEEAA通用标准）
R1. 工程知识：掌握数学、自然科学、工程基础和专业知识，能用于解决复杂程序设计问题。
R2. 问题分析：能应用数学、科学和工程原理识别、表达、并通过文献研究分析复杂编程问题，以获得有效结论。
R3. 设计/开发解决方案：能针对复杂软件系统需求，设计解决方案，开发满足特定需求的模块或系统，并在设计环节体现创新意识，考虑社会、健康、安全、法律、文化及环境等因素。
R4. 研究：能基于科学原理并采用科学方法对复杂软件工程问题进行研究，包括设计实验、分析与解释数据、并通过信息综合得到合理有效的结论。
R5. 使用现代工具：能针对复杂软件工程问题，开发、选择与使用恰当的技术、资源、现代工程工具和信息技术工具，包括预测与模拟，并理解其局限性。
R6. 工程与社会：能基于软件工程相关背景知识进行合理分析，评价专业工程实践和复杂软件系统解决方案对社会、健康、安全、法律以及文化的影响，并理解应承担的责任。
R7. 环境和可持续发展：能理解和评价针对复杂软件工程问题的专业工程实践对环境、社会可持续发展的影响。
R8. 职业规范：具有人文社会科学素养、社会责任感，能在软件工程实践中理解并遵守工程职业道德和规范，履行责任。
R9. 个人和团队：能够在多学科背景下的团队中承担个体、团队成员以及负责人的角色。
R10. 沟通：能够就复杂软件工程问题与业界同行及社会公众进行有效沟通和交流，包括撰写报告和设计文稿、陈述发言、清晰表达或回应指令，并具备一定的国际视野，能在跨文化背景下进行沟通和交流。
R11. 项目管理：理解并掌握软件工程管理原理与经济决策方法，并能在多学科环境中应用。
R12. 终身学习：具有自主学习和终身学习的意识，有不断学习和适应发展的能力。

## 二、课程总体框架（OBE支撑映射）
- 通识基础课程：32学分 → 支撑 R1, R6, R7, R8, R10, R12
- 专业基础课程：28学分 → 支撑 R1, R2, R4, R5, R12
- 专业核心课程：36学分 → 支撑 R1-R5, R9, R11
- 实践教学环节：30学分 → 支撑 R3, R4, R5, R9, R11, R12
- 选修课程：14学分 → 支撑 R3, R7, R10, R12
- **总计：140学分**

## 四、专业核心课程说明（OBE目标-内容-考核闭环）

### 数据结构与算法（4学分）
**课程目标（CO1-CO4）**：
- CO1：能准确描述线性、树、图等抽象数据类型及其存储结构（支撑R1,R2）
- CO2：能运用时间/空间复杂度分析法评估算法效率（支撑R2,R4）
- CO3：能独立设计并实现动态规划、贪心等策略解决中等难度编程问题（支撑R3,R4）
- CO4：能通过单元测试与性能测试验证算法正确性与鲁棒性（支撑R4,R5）
**考核方式**：
- 平时作业（20%）：LeetCode在线评测（自动判分）
- 期中考试（25%）：手写算法伪代码与复杂度分析
- 课程设计（30%）：企业级文本处理工具开发（Git提交记录+代码审查报告）
- 期末考试（25%）：综合算法设计与故障诊断

### 面向对象程序设计（4学分）
**课程目标（CO1-CO4）**：
- CO1：能运用UML类图/时序图建模真实业务场景（支撑R1,R3）
- CO2：能基于SOLID原则重构遗留代码提升可维护性（支撑R3,R5）
- CO3：能集成第三方SDK（如支付、地图）完成模块开发（支撑R5）
- CO4：能撰写符合行业规范的API文档与技术报告（支撑R10）
**考核方式**：
- GitHub代码仓库（40%）：含CI流水线状态、PR合并率、代码覆盖率报告
- 结对编程考核（20%）：现场协作解决Bug并答辩
- 技术文档（20%）：Swagger API文档+用户手册
- 期末笔试（20%）：设计模式应用与异常处理方案

### 企业级系统集成实践（4学分）
**课程目标（CO1-CO4）**：
- CO1：能分析ERP/CRM系统接口文档并制定集成方案（支撑R2,R3）
- CO2：能使用OAuth2.0实现安全授权与数据同步（支撑R5,R6）
- CO3：能设计消息队列解耦方案应对高并发场景（支撑R3,R4）
- CO4：能编写集成测试用例并生成质量报告（支撑R4,R11）
**考核方式**：
- 企业验收报告（50%）：由合作企业签署技术达标确认书
- 架构设计答辩（30%）：含安全性、可扩展性、可观测性评估
- CI/CD流水线（20%）：自动化测试通过率≥95%，部署成功率100%

### 人工智能技术应用专题（3学分）
**课程目标（CO1-CO3）**：
- CO1：能基于HuggingFace模型微调垂直领域NLP任务（支撑R1,R3）
- CO2：能构建LangChain智能体解决多步骤业务流程（支撑R3,R5）
- CO3：能评估AI生成内容的合规性与偏见风险（支撑R6,R7,R8）
**考核方式**：
- 模型部署Demo（40%）：Docker容器化+API响应延迟≤500ms
- Prompt工程报告（30%）：含A/B测试结果与伦理影响分析
- 技术分享（30%）：面向低年级学生讲解原理与实践

## 五、实践教学环节（OBE达成度评价机制）

### 课程实验
- 实施“能力锚点”考核：每门课实验设置3-5个关键能力锚点（如“CO3-算法实现”），学生须在Git提交中明确标注对应锚点，教师按锚点逐项评价达成度（未达成/基本达成/完全达成）。

### 课程设计
- 引入“双盲评审”：校内教师与企业工程师独立评分，差异＞20%启动复议；成果需包含《能力达成自评表》，对照R1-R12逐条说明证据链（代码行、文档页、测试报告编号）。

### 实习实训
- 执行“三维度评价”：
  - 企业导师评价（40%）：基于《程序员实习能力量表》（含代码质量、协作效率、问题解决等12项指标）
  - 校内导师评价（30%）：实习日志、周报、中期报告质量
  - 学生自评与互评（30%）：团队协作贡献度、技术分享频次
- 达成度阈值：单项能力得分＜70%者须参加暑期强化实训

### 毕业设计
- 构建“四阶达成度雷达图”：
  - 开题阶段：评估R1,R2,R3达成度（文献综述深度、技术路线可行性）
  - 中期阶段：评估R4,R5,R11达成度（实验设计合理性、工具链完备性、项目管理规范性）
  - 预答辩阶段：评估R6,R7,R8,R10,R12达成度（伦理合规性、可持续性分析、技术表达能力、自主学习证据）
  - 终期答辩：R1-R12全覆盖终审，未达标的毕业生进入“能力补强计划”
- 成果存档：所有毕业设计材料上传至校级OBE数据平台，支持能力达成度年度统计分析与课程持续改进。
